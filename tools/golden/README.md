# Golden UI regression

A visual-regression check for the on-screen UI. It renders the display preview
catalog (the `Test*Previews` in `echod/internal/feature/display`, the same scenes
`SHOW_PREVIEW` / `SPOT_PREVIEW` write) and compares a curated subset against the
committed PNGs in `images/`. The renderer is deterministic, so a byte difference
means a screen's look changed.

The screens checked are listed in `screens.txt` (one `show/...` or `spot/...`
path per line) — about 140 of them, picked for breadth across the clock faces,
calendar, music library, now playing, calls, cameras, announcements, dashboards,
weather, settings, first run and the Spot. It is a curated subset, not every
render: the full catalog is ~2,000 images, far too large to keep as baselines.

## Running it

From the repo root, with the Go toolchain on `PATH`:

```sh
bash tools/golden/run.sh              # check; non-zero exit if any screen changed
BLESS_GOLDEN=1 bash tools/golden/run.sh   # accept the current look as the new baseline
```

This is a release-gate step (see the release checklist). When a code change is
meant to change a screen, run it, eyeball the screens it names, then bless and
commit the updated PNGs in the same commit as the code, so the diff shows what
moved.

## Notes

- The baselines are generated by rendering; regenerate them (bless) if the Go
  toolchain or the fonts change, since those can shift pixels.
- Adding a screen: add its rendered filename to `screens.txt` and bless. Find the
  filename by running the preview test with `SHOW_PREVIEW` / `SPOT_PREVIEW` set to
  a directory and listing it.
- The `c64-techo5basic` easter-egg screen is deliberately left out: it is the one
  preview that is not deterministic.
