# The device's own voice

A device that has to say something — "What's the announcement?" before it records one — cannot
synthesise it. Piper builds for armv7 and runs (`tools/linux/build-piper.sh`), and on an Echo Spot it
takes sixteen seconds to load a model and then speaks at 1.8 times slower than real time, which is
not speech, it is a pause. eSpeak NG is packaged for armv7 and speaks any language instantly, and
sounds like an answering machine from 1995.

So the device plays **clips rendered by Piper when the image is built**, on a machine where Piper is
instant. Nobody records anything: the phrase is written as text, Piper speaks it, the wav is shipped.
Adding a language is a line of text and another render.

## Which voice, and why it is not a free choice

Shipping generated audio means shipping something derived from the voice model, which is derived from
the data it was trained on. Two things have to be permissive, and only one of them is obvious:

1. **The dataset licence**, which the model card names.
2. **What the voice was fine-tuned from.** Most Piper voices are fine-tuned from `en_US-lessac` or
   `en_US-ryan`, and both are a problem: lessac is trained on Blizzard 2013 data that has to be
   requested individually and may not be redistributed, and ryan's data is CC BY-**NC**-SA, which
   rules out anything but non-commercial use. A voice with a CC0 dataset that was fine-tuned from one
   of those carries the base model's provenance with it: `de_DE-thorsten` and `es_ES-davefx` are CC0
   datasets sitting on exactly that foundation.

A voice is only safe here when the dataset is permissive **and** it was trained from scratch.

## The set that passes both tests

| Language | Voice | Dataset | Trained |
|---|---|---|---|
| English (US) | `en_US-ljspeech` | public domain (LJ Speech) | from scratch |
| German | `de_DE-mls` | CC BY 4.0 | from scratch |
| Spanish | `es_ES-carlfm` | public domain | from scratch |
| French | `fr_FR-mls` | CC BY 4.0 | from scratch |
| Italian | `it_IT-serena` | CC BY 4.0 | from scratch |
| Dutch | `nl_NL-mls` | CC BY 4.0 | from scratch |

Those are the six languages the screen already listens in (`lib/triggers`). The CC BY ones want
attribution wherever the clips ship; `licenses/` is the place for it.

**Italian took the longest to settle** and is worth the note. `it_IT-riccardo` is trained from
scratch, but its dataset is M-AILABS, whose licence page says "see URL" and whose URL no longer
resolves — an unverifiable licence is not a licence. `it_IT-paola` has a CC0 dataset and is fine-tuned
from lessac, so the CC0 buys nothing. `it_IT-serena` is CC BY 4.0 and trained from scratch; its audio
was generated by Qwen3-TTS, which is Apache 2.0, from Tatoeba sentences, which are CC BY. Every link
in that chain is checkable, which is the whole point.

## What this is not

Not a text-to-speech engine on the device, and not a voice for arbitrary sentences. The device can
say what we wrote down in advance, in the languages we rendered. Anything else — reading out a
message that arrived as text, say — is Home Assistant's text-to-speech played to the device, which
already works.
